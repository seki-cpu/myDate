# myDate V2 Date Content Tags

## Purpose

V2 content discovery should describe the experience the user wants now, not a relationship stage.

Do not tag Date Ideas as `dating-stage`, `early-relationship`, `honeymoon`, `stable-couple`, or other relationship-progression concepts.

`categories` remain the broad Architect-owned `DateCategory[]` values. `tags` are lightweight content metadata and do not change the shared type.

## Broad categories

Use the existing canonical categories only:

- `food`
- `outdoor`
- `indoor`
- `creative`
- `romantic`
- `relaxing`
- `adventure`
- `random`

A Date Idea may have more than one category when that improves discovery.

## Tagging rules

1. Prefer 4–6 useful tags per card.
2. Include at least one energy/social/context tag when possible.
3. Do not duplicate category names mechanically unless the tag is useful for future filtering.
4. Do not use tags that imply relationship success, permanence, intimacy level, or progression.
5. `private` describes the physical/social setting only; it does not imply sexual or romantic intimacy.
6. `romantic` remains a broad optional category, not a relationship-stage label.
7. Memory Prompt wording stays independent from tags and remains user-owned experience content.
